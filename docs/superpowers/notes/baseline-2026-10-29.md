# Baseline for `django6-work` (2026-10-29)

Branch state: upstream `main` + PR #232 (Django 6.0.3, `psycopg` 3.3.3).

## Django 6.1 minimums (from the 6.1 release notes)

- Python: 3.12, 3.13, 3.14, 3.15 (3.15 as of 6.1.3).
- PostgreSQL: **15 and higher** (14 dropped). CI minimum is therefore 15, not 13/14 as the earlier draft assumed.
- `psycopg`: no minimum stated by Django; `psycopg` 3.2+ for `HStoreField` introspection.

## Removed in 6.1 (relevant check list)

`staticfiles.finders.find(all=)`, `login()` fallback to `request.user`,
`ordering=` argument of `ArrayAgg`/`JSONBAgg`/`StringAgg`, `RemoteUserMiddleware`
subclasses without `aprocess_request()`.

## Deprecated in 6.1 (will fail with `-W error::DeprecationWarning`)

Email settings (`EMAIL_BACKEND`, `EMAIL_HOST`, ... -> `MAILERS`), `mail.get_connection()`,
`select_related()` without arguments, `values_list(flat=True)` without a field,
`Model.from_db()` without `fetch_mode`, `None` for JSON `null` queries (`JSONNull`),
`transaction.savepoint()`, `get_placeholder`, `quote_name_unless_alias()`, `salted_hmac()`
default algorithm. Behaviour changes: SQL aliases always quoted (raw SQL with mixed-case aliases),
default ordering applies to `union()`/`intersection()`/`difference()`, `first()`/`last()` no
longer order by pk after `order_by()`.

## Environment notes

- `psycopg` needs `libpq`; on macOS without it install `psycopg[binary]` in the venv (the Docker image has `libpq5`).
- `requirements-tests.txt` pins `pytest==7.2.1` and conflicts with `requirements-devel.txt`; do not install both.
- Tests need PostgreSQL with role `taiga`/`taiga` (superuser) on `127.0.0.1:5432` (`settings/common.py`).

## Baseline test run (Django 6.0.3, Python 3.12, PostgreSQL 15)

- Full suite, `pytest -n 4 --reuse-db`: **1756 passed, 7 failed** in 12m38s (1763 tests).
- All 7 failures are in `tests/integration/test_importer_api.py` with
  `relation "references_projectNNN" does not exist` (sequence created by a signal
  not visible to the parallel worker). Rerunning that file serially:
  **68 passed**. So the failures come from `pytest-xdist`, not from the code.
- Full serial run does not fit the 120 s tool limit of this environment; use
  `-n 4` and treat `test_importer_api.py` separately (serial).
- The suite is warning-heavy (15568 warnings); Task 3 reads them for Django 6.1 deprecations.
