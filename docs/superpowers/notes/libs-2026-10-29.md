# Kaleidos libraries and plugins on Django 6.1 (2026-10-29)

Checked in the venv with Django 6.1.2, Python 3.12, PostgreSQL 15.

| Library | Version | Result |
|---|---|---|
| `django-sites` | 0.11 | imports; legacy imports sit inside `try`/fallback |
| `djmail` | 2.0.0 | imports, mail sending covered by the test suite |
| `django-sr` | 0.0.4 | imports, app loads (`manage.py check` clean) |
| `django-jinja` | 2.11.0 | imports, templates render in the test suite |
| `serpy` | 0.3.1 | imports, serializers used throughout the suite |
| `django-sampledatahelper` | 0.5 | `sampledatahelper.helper` (the only part Taiga uses) works; `sampledatahelper.model_helper` fails with `ImportError: cannot import name 'FieldDoesNotExist' from 'django.db.models.fields'` but nothing imports it. `manage.py sample_data` on the fork produced 7 projects, 114 user stories, 15 users, identical to the original code. |

The earlier suspicion that `models.NullBooleanField` would break these libraries was wrong,
see the correction in `baseline-2026-10-29.md`. No library needed vendoring.

## Plugins

Pins in `requirements-contribs.in` and `.txt` changed to tag `6.10.0` (the newest tag; `6.10.2` does not exist,
`6.8.0` was stale). All four install and load as `INSTALLED_APPS` entries
(`taiga_contrib_github_auth`, `taiga_contrib_gitlab_auth`, `taiga_contrib_slack`, `taiga_contrib_protected`);
`manage.py check` reports no issues and no deprecation warnings. Their own behaviour (OAuth flows, Slack hooks)
is not exercised here.

Packaging problem found: the `taiga-contrib-gitlab-auth-official` distribution installs a top-level `tests` package
into `site-packages` that shadows nothing today (the repository's own `tests` wins) but is a trap; not fixed here.
